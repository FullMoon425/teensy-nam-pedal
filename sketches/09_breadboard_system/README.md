# 09_breadboard_system

입력 버퍼, 오디오실드, 조작계, OLED를 브레드보드 하나에 올려 **NAM 없는 페달 전체**를 확인합니다 (H2).
[08_ui_integration](../08_ui_integration)의 UI에 실제 오디오를 붙인 것입니다. 노브가 소리를 바꾸고, 미터는 실제 피크를 보여 줍니다.
**02, 06(48kHz 확인), 08을 통과한 뒤에** 돌립니다.

```
기타 → 입력 버퍼(9V) → 실드 LINE IN
  → [Peak IN] → Gain + 소프트 클리퍼(tanh, NAM 자리) → EQ 3밴드 → Master → 바이패스 페이드 → [Peak OUT]
  → 실드 LINE OUT / 헤드폰
```

| 블록 | 구현 | 범위 |
|---|---|---|
| Gain + 클리퍼 | float 처리, 블록마다 게인 램프, `0.7 * tanh(x / 0.7)` | -12~+24dB |
| EQ | `AudioFilterBiquad` 3단: 로우셸프 120Hz / 피킹 700Hz Q 0.7(RBJ 계수 직접 계산) / 하이셸프 3kHz | 각 ±12dB |
| Master | float 처리, 블록마다 게인 램프 | -40~+6dB |
| 바이패스 | `AudioEffectFade` 두 개로 8ms 크로스페이드 | |
| Gate | **화면에만 있음, 처리 없음** (다음 단계에서 `dsp/Gate`로) | |

## 브레드보드 구성 (중요)
- **입력 버퍼는 9V 어댑터로 따로 공급**합니다. TL072/OPA2134는 USB 5V 단전원으로는 제대로 동작하지 않습니다(OPA2134는 5V에서 입력 동작 범위가 사실상 없음). Vref = 4.5V.
- 버퍼 출력은 **반드시 결합 캐패시터를 거쳐** LINE IN으로만 갑니다. 9V가 Teensy 핀에 닿는 곳이 없어야 합니다.
- 9V GND와 Teensy GND는 **한 점에서** 합칩니다(스타 접지). 오디오 GND와 OLED·포트 GND는 브레드보드 레일을 따로 씁니다.
- 입력 버퍼의 + 입력(1MΩ 바이어스)은 고임피던스라 잡음을 아주 잘 받습니다. **OLED SPI 선(11, 13)과 최대한 멀리**, 기타 입력 선은 짧게.
- 출력 버퍼는 아직 없으므로 실드 헤드폰 잭이나 LINE OUT으로 바로 듣습니다. **처음엔 볼륨을 작게.**
- 배선 상세: [hardware-design.md](../../docs/hardware-design.md) 3-1절(입력 버퍼), 03/04 README(조작계, OLED)

## 조작계 없이 먼저 시험할 때
전원부, 입출력 버퍼, OLED만 연결한 상태에서도 돌릴 수 있습니다.
- **포트가 없으면 `src/main.cpp`의 `USE_POTS`를 0으로.** 아날로그 핀이 떠 있으면 값이 제멋대로 움직여 Gain/Master가 튀고, 갑자기 큰 소리가 날 수 있습니다.
- 인코더·풋스위치 핀은 내부 풀업이라 안 달아도 안전합니다. 바이패스는 `b`, 프리셋은 `n`으로 바꿉니다.
- 시작 프리셋은 1번 Flat Test(모든 값 0dB)입니다.

## 시리얼 명령
| 키 | 동작 |
|---|---|
| `o` | 화면 갱신 끄기/켜기 (찌직 잡음이 OLED 때문인지 A/B) |
| `f` | 프레임 20 / 5 / 1fps 순환 |
| `b` | 바이패스 (풋스위치 없이) |
| `l` / `L` | `lineInLevel` 내림(더 큰 입력 허용) / 올림(더 민감) |
| `s` | 1초 통계 출력 켜기/끄기 |
| `p` | 포트 읽기 켜기/끄기 (다시 켜면 잠금 상태에서 시작) |
| `n` | 다음 프리셋 (인코더·풋스위치 없이 시험할 때) |

1초마다 `[통계]` 줄이 나옵니다: CPU%, 오디오 메모리 최대, IN/OUT 최대 dBFS와 클립 횟수, 화면 전송 시간, 루프 최대 us.

## 화면
08과 같고, 미터만 실제 값입니다. 미터는 -48~0dBFS, 세로선은 1초 피크 홀드입니다. -0.5dBFS 이상이면 `I`/`O` 글자가 1초 동안 반전(CLIP)됩니다.
프리셋 1번 **Flat Test**는 EQ 0dB, Gain 0dB, Master 0dB라서 바이패스와 음량이 같아야 합니다.

## 통과 기준
1. Flat Test에서 바이패스와 이펙트의 음량이 같고(약하게 칠 때. 세게 치면 클리퍼가 눌러서 약간 작아짐), 전환 때 딸깍 소리 없음
2. 노브를 돌리면 소리가 바로 바뀌고, 돌리는 동안 지퍼 잡음(지직지직) 없음
3. 기타 볼륨 0, Master를 높게 두고 `o`로 화면을 켜고 꺼 봐도 잡음 차이 없음 (04 통과 기준의 실제 검증)
4. 오디오가 도는 중에도 포트가 08과 같이 안정적임
5. 가장 세게 쳐도 IN에 CLIP이 안 뜨고 피크가 -3dBFS 이하로 남는 가장 큰 `lineInLevel`을 `l`/`L`로 찾아 [hardware-design.md](../../docs/hardware-design.md) 3-1절에 기록
6. `[통계]`의 CPU%(최대), 오디오 메모리 최대, 루프 최대 us 기록. NAM이 쓸 수 있는 여유의 기준선이 됨

## 안 될 때
- 소리가 안 남: 02 단독으로 먼저 확인. 바이패스(`b`)로 바꿨을 때만 나오면 DSP 쪽, 둘 다 안 나오면 배선·실드
- 음이 반음 가까이 높거나 낮음: 48kHz 설정 불일치. 06으로 확인 (시작 메시지의 `SYS_FS 48k 설정`이 성공인지)
- 험(웅~): 노트북 충전기를 빼고 배터리로. 그래도 나면 9V와 Teensy GND를 한 점에서 합쳤는지
- 찌직 잡음이 `o`로 화면을 끄면 사라짐: OLED SPI 선과 입력 버퍼를 멀리, OLED 전원·GND를 오디오와 다른 레일로. `f`로 fps를 낮추면 잡음 간격이 바뀌는지도 확인
- 노브 돌릴 때 지직거림: EQ 노브만 그렇다면 Biquad 계수 교체 때문 (Gain/Master는 램프 처리됨). 기록해 두고 펌웨어 `dsp/Biquad`에서 계수 보간으로 해결
- IN에 CLIP이 자주 뜸: `l`로 lineInLevel을 내림 (0이 가장 큰 입력 3.12Vpp)
